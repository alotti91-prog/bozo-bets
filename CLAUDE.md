# Bozo Bets: notes for Claude

Weekly group-parlay tracker for a group of friends. React (Vite, plain JavaScript) on Vercel, Supabase for data, auth, and realtime. The owners are not professional developers: explain changes plainly and keep the code simple.

## Commands
- `npm run demo`: run with built-in sample data, no backend (best for UI work)
- `npm run dev`: run against Supabase (needs `.env.local`, see `.env.example`)
- `npm test`: unit tests for odds, standings, wheel, and recap math (`src/lib/*.test.js`)
- `npm run test:sql`: runs `supabase/schema.sql` in PGlite and checks the permission rules
- `npm run build`: production build

Run all three checks before saying a change is done.

## How it fits together
- `supabase/schema.sql` is the whole backend: tables, row-level security, server functions (`create_league`, `join_league`, `claim_player`, `spin_wheel`, …), and the realtime publication. Keep it re-runnable (`if not exists`, `create or replace`, `drop policy if exists`). Any new rule needs a check in `scripts/sql-dryrun.mjs`, which also checks re-running the file and upgrading from the first version (`scripts/fixtures/schema-v1.sql`). When a function's arguments change, add `drop function if exists` for the old signature and update the grant lists.
- Pick deadline: `leagues.lock_dow/lock_time/lock_tz` is the weekly rule; `weeks.lock_at` is the per-week deadline (null = none). `week_open()` in SQL and `lockState()` in `src/lib/deadline.js` decide if a week is locked. Admins bypass the lock.
- Week numbers follow NFL weeks and can have gaps. The current week is always the highest `n`; "last week" means the closest lower `n`. `src/lib/nfl.js` works out the current NFL week.
- Links back to the app (invites, sign-in emails) use `siteUrl()` from `src/lib/site.js`, never `window.location.origin`, so they point at the public Vercel address.
- Permissions are enforced in the database. UI checks (`isAdmin`, `me`) only hide buttons. Admins can switch on Settings → Member view (`asMember` in `League.jsx`, resets on reload): it passes `isAdmin`/`isOwner` as false, so every screen must take admin-ness from those props, never from `member.role` directly.
- The wheel eliminates: `spin_wheel()` knocks names out at random until one is left and saves the order in `spins.eliminated`; `landed_id` is always the bozo (the last name left), so the payer, standings, and History only ever read `landed_id`. Older spins have no `eliminated` and were a single spin onto the bozo. `spinRounds()` in `wheel.js` turns either kind into the spins to play; `WheelTab` plays them, and `spinMs()` sets how long refreshes wait so the payer isn't spoiled mid-spin.
- `src/lib/useLeague.js` loads every row for a league and re-fetches on any realtime change. Screens get `data = { league, players, members, weeks, legs, spins, reactions, comments, views }` (`views` = spin ids you've watched, or null if the table isn't there).
- Until you watch the latest spin, `League.jsx` passes the tabs a masked copy of the data (`unwatchedSpin` + `hideSpin` in `wheel.js`): that week's spins are flagged `hidden` and the payer they set is blanked with `payer_hidden`. Any new place that shows a spin result or payer must respect those flags.
- The weekly recap (`screens/RecapSheet.jsx`, data from `weekRecap()` in `src/lib/recap.js`) opens a beat after you first watch a spin (`markWatched` in `League.jsx`), and again from History or the Wheel tab. `weekRecap` returns null while the spin is hidden. Faces (`components/BozoFace.jsx`, an original drawing that keeps its colors in dark mode): the wheel's pick in a busted week is `full`; a lost leg is `paint`, `makeup`, or `wig` by how far it missed (`lossTier()`/`cutoffs()` read `legs.margin`, which `WeekTab`'s grade saves via `gradeMargin()` when the final score agrees; for typed legs, or picked legs graded before the final, the commish picks Close call/Regular/Blowout in `week/MissPicker.jsx`, saved as `legs.miss`, which wins over margin; the leg guard lets only the commish set either, un-grading clears margin, and any result but Lost clears miss); no leg is `makeup`; a win or push is `clean`. Above the list, `recap/FaceLadder.jsx` shows all five faces with counts (`faceCounts()`), and tapping it opens `recap/FaceRules.jsx`, whose cutoffs table comes from `cutoffRows()` so it matches `CUTOFFS`. Opening the app to an unwatched spin shows `WatchPrompt`; its Watch, and "Watch spin" on This week, send `watchNow` so `WheelTab` replays straight away.
- One-tap grading: when 2+ picked legs are final but ungraded, `WeekTab` shows "Grade all" for admins (`finishedGrades()` in `bets.js`), saving each grade with its margin. History's "Edit Week" (`save_past_week()`) edits legs in place, so reactions, comments, `bet`, `margin`, and `miss` survive unless the pick or result they depend on changed.
- Settings → Weeks → "Go back to an earlier week" (`settings/ResetWeekForm.jsx`, `reset_to_week()` in SQL, commish only) deletes every later week, undoes that week's spins, and can clear its grades. The app then removes the deleted weeks' slip photos from Storage.
- A week's slip screenshots are `weeks.slip_paths` (read them with `slipPaths()` in `src/lib/slip.js`; older weeks only have `slip_path`). Added with `add_slips()`, removed with `remove_slip()`; the first one marks the bet placed. Files sit at `<league>/<week>/…` in the private Storage bucket `slips` (set up at the bottom of `schema.sql`, skipped when there's no `storage` schema, as in tests). The demo client fakes `storage.from().upload/createSignedUrl`.
- Live legs: a leg picked from a game stores `legs.bet` (jsonb: sport, game, type, side, line, player, stat; see `src/lib/bets.js`). Free-text legs have none. Scores come from ESPN's public, unofficial feed through the Vercel function `api/espn.js`, which only allows requests `espnUrl()` builds, trims responses with `src/lib/espn.js`, and sets CDN caching. The app calls it via `src/lib/scores.js` (`demoScores` in demo mode; straight to ESPN in `npm run dev`, which has no `/api`). `useLiveGames` polls only unfinished games while the app is on screen. If the feed breaks, legs show no live line; nothing else may depend on it.
- DraftKings lines: `normalizeScoreboard()` keeps each game's board as `odds.board` (`oddsBoard()` in `src/lib/espn.js`: both sides of the spread with prices, both moneylines, the total with over/under prices; any part can be missing). `boardOptions()`/`pickFromBoard()` in `bets.js` turn a tapped price into picker state plus odds; board games offer no hand-built spread/total/moneyline (no alternate lines; "Type it instead" covers them), only "Player props" on football, which opens `PropPicker` straight away; games without a board (no lines, or started) still build by hand with the kind-of-bet row; `boardPrice()` prices an older hand-built leg being edited, and `LegForm` clears an auto-filled price (`oddsAuto`) once the bet moves off the board or off DraftKings' prop line. `components/GameCard.jsx` draws a board, tappable in `BetPicker` (Add a leg) and read-only in `week/LinesSheet.jsx` (This week's lines). Boards show only for games that haven't started; ESPN has no prop lines, so props stay hand-built, in `components/PropPicker.jsx`: category → stat → player (`PROP_CATS`, `STAT_POS`, `propPlayers()` in `bets.js`; football only). For the NFL, starters come first and injuries get tags, from Sleeper's free API: `api/depth.js` fetches the ~5MB player list (Sleeper asks for once a day at most), `normalizeDepth()` in `src/lib/depth.js` trims it to `{ o, s }` per player, keyed by ESPN id and by `n:` + `nameKey()` (Sleeper lacks ESPN ids for many players; read it with `depthOf()`), and the CDN caches it a day; players Sleeper couldn't match are never hidden; the slip's `LegRow` shows the same tag (`components/InjuryTag.jsx`) on NFL props until kickoff, via `legInjury()`; the app reads it with `getDepth()` in `scores.js` (`demoDepth` in demo mode, null in `npm run dev`). If it's missing, everyone shows A–Z; nothing else may depend on it. DraftKings prop lines come from SportsGameOdds (free plan: 2,500 games a month, 10 requests a minute, every response counts as at least one game): `api/props.js` takes `home`, `away`, and kickoff rounded to the hour (`parsePropsQuery()` refuses anything else so made-up URLs can't spend the allowance), asks by the home team's id with a kickoff window, falls back to every game in that window matched by name (`findEvent()`), trims to DraftKings' full-game lines keyed by `nameKey` (`normalizeProps()` in `src/lib/props.js`), and caches 30 minutes. The key is the Vercel env var `SPORTSGAMEODDS_KEY` (server only, never `VITE_`). The app reads it with `getProps()` in `scores.js` (`demoProps`: NE @ CHI only); `PropPicker` shows each player's line and fills the number, and `BetPicker` passes `propPrice()` like `boardPrice()`. Without the key, or if it's down, props are typed as before.
- `api/health.js` checks Supabase (a read with the public key), ESPN, and Sleeper (its tiny `/state/nfl`, never the 5MB list), answering 200 or 503 with which one failed. It reports `props` (is `SPORTSGAMEODDS_KEY` set) without calling SportsGameOdds and without failing on it. An uptime monitor watches it. Keep it read-only and fast; add a check there when the app gains another outside dependency.
- Sunday sweat mode: `week/useSweat.js` watches the slip's legs (`legOutcome()`/`sweatEvents()` in `src/lib/sweat.js`: the grade first, else a final or locked live line). News that happens while the slip is on screen gets a toast (`sweatMessage()`), the clown horn and a shake for a bust (`.leg.is-shake`), a ding and confetti for a cash (`confetti()` in `src/lib/fx.js`), the big shower when the slip hits; opening the app only takes stock, and a feed blink isn't news. When nothing has busted and one leg is left, `carrier()` puts "It's all on …" above the legs and highlights that leg (`.carry`, `.leg.is-carry`). Sounds follow the Wheel tab's sound switch; confetti and shakes respect reduced motion.
- Pure logic lives in `src/lib/odds.js`, `stats.js`, `wheel.js`, `espn.js`, `bets.js`, `depth.js`, `props.js`, `sweat.js`, and `recap.js`, with tests (`logic.test.js`, `recap.test.js`, `props.test.js`, `sweat.test.js`). Put new math there, not in components.
- `src/lib/demo-supabase.js` fakes the Supabase calls the app uses. If you add a new query or RPC, add it there too so `npm run demo` keeps working.
- Swiping left or right changes tabs (`src/lib/swipe.js`, wired in `League.jsx`). Anything that needs its own sideways swipe or drag must carry `data-noswipe`.
- Screens: tabs sit in a bottom bar (`.tabbar` in `League.jsx`). `src/screens/WeekTab.jsx` is the This week tab: the summary row (`.glance`), the slip, and the actions. Its pieces are in `src/screens/week/`: `LegRow` (one line per leg; tapping opens `LegSheet`, the leg's panel with reactions, comments, grade, edit, remove), `LegForm` (shown inside a `Sheet`), `LiveLine`, `PayoutForm`. `WheelTab.jsx` plays spins through `wheel/useSpinPlayer.js` and lists them with `wheel/WheelLog.jsx`. `SettingsSheet.jsx` is a list of rows; each row opens a page from `src/screens/settings/` inside the same sheet (`Sheet` takes `onBack`). Keep code files under about 300 lines; when one grows past that, move a self-contained piece out next to it.
- Styling is one file, `src/styles.css`, with color tokens on `:root` and a dark-mode override. Use the tokens rather than new hard-coded colors. One font (Figtree) for everything; Alfa Slab One only for the wordmark, page titles (`.page-title`), and the wheel's result (also the recap's headline, `.recap-big`). Labels are sentence case, not all caps. Each tab's content sits in `.pane`, which spaces its sections, so new sections need no margins. The slip uses the `--paper-*` tokens, which stay light in dark mode. Reuse the building blocks: `.glance`, `.rows`/`.row`, `.segmented`, `.choices`, `.switch`, `.text-btn`, `Sheet`.

## Conventions
- Copy is short and plain. Errors say what happened and what to do.
- Record notable choices in `DECISIONS.md` (date · decision · why).
- When a change people will notice ships, add a plain-language entry at the top of `src/lib/releases.js` (admins see it in Settings → What's new, with a dot on the gear). Credit whoever asked for it with `idea: 'Name'`.
- Never commit `.env.local` or any Supabase secret key. The publishable key is meant to be public.
- `main` is protected by a GitHub ruleset and every push to it goes live. The repo owner can push directly. Everyone else: work on a branch, run the three checks, and open a pull request for the owner to approve. Vercel builds a preview for each pull request.
